Positional encodings, from sinusoids to RoPE

A long read, about 9 minutes

Attention compares every token with every other token at once. That is what makes it fast on a GPU, and also what makes it blind: a bag of words and a sentence look the same to it. Positional encodings are how a Transformer gets word order back.

Why attention forgets order

An attention layer takes a weighted sum over the values, with weights from query–key dot products. Shuffle the input tokens and you shuffle the outputs the same way; nothing in the sum knows which token came first. In other words, attention is permutation equivariant.

So something has to be added to each token that says where it sits.

Sinusoids: adding position

The original Transformer adds a fixed vector to each embedding: sines and cosines of the position at many frequencies, PE(pos, 2i) = sin(pos / 10000^(2i/d)). Low dimensions spin fast, high ones slowly, like the hands of a clock.

Because a shift in position is a linear map on these vectors, the model can learn to attend by relative offset. But the position is mixed into the content, and every layer has to untangle it again.

RoPE: rotating instead

Rotary embeddings do not add anything. They rotate each pair of query and key dimensions by an angle proportional to the position. When a query at position m meets a key at position n, the two rotations cancel down to one rotation by m − n.

The attention score then depends only on the content and the relative distance, which is exactly what we wanted, and it costs nothing extra to store.

What to take away

Sinusoids tell each token where it is. RoPE tells each pair of tokens how far apart they are. Most large language models today use the second.
